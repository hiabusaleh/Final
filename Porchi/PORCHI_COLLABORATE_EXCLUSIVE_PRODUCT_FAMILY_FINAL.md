# PORCHI COLLABORATE — EXCLUSIVE PRODUCT FAMILY
## Final Product Plan — 2026

**Master Brand:** Porchi  
**Product:** Porchi IELTS  
**Product Family:** Porchi Collaborate  
**Core idea:** Learn alone. Practice with people. Improve together.

---

# 1. PRODUCT FAMILY VISION

Porchi Collaborate is not a social network and not a generic video-call feature.

It is a **purpose-built human learning layer inside the Porchi IELTS ecosystem**.

The learner should be able to move naturally between:

```text
Learn
  ↓
Practice Alone
  ↓
Practice With Humans
  ↓
Collaborate
  ↓
Feedback
  ↓
Repair
  ↓
Retest
  ↓
Progress
```

The five flagship products are:

```text
PORCHI COLLABORATE
│
├── 01. Speaking Partner
├── 02. Study Rooms
├── 03. Speaking Role-Rotation
├── 04. Skill-Swap Matching
└── 05. Study Session Replay
```

These five features should be designed as one connected system rather than five unrelated tools.

# 5. SHARED LEARNING SURFACE

This is the most important technical/product concept in Study Rooms.

Porchi should not simply become a Zoom-style room with screen sharing.

Instead, the Porchi learning surface itself becomes collaborative.

Example:

```text
Student A opens:
Reading → Passage 2 → Question 14

Student B and C automatically see:
Reading → Passage 2 → Question 14
```

If Student A highlights evidence, the room can see the shared highlight.

If Student B adds a shared note, everyone can see it.

If Student C points to a sentence, everyone sees the pointer.

This creates:

> **Shared IELTS Content + Live Human Collaboration**

# 6. PERSONAL VS SHARED ANNOTATION

Every annotation system should have two states.

### Personal

```text

My Note
My Bookmark
```

Visible only to the learner.

### Shared

```text

Shared Note
Shared Pointer
Shared Drawing
```

Visible to the room.

This distinction is mandatory because learners need private thinking space even while collaborating.

# 8. 03 — SPEAKING ROLE-ROTATION

## Purpose

Turn group speaking practice into structured IELTS simulation.

### Core concept

Three learners rotate through three roles:

```text
Candidate
Examiner
Observer
```

Example:

```text
Round 1
A → Candidate
B → Examiner
C → Observer

Round 2
B → Candidate
C → Examiner
A → Observer

Round 3
C → Candidate
A → Examiner
B → Observer
```

Every participant experiences all three perspectives.

---

# 9. ROLE-ROTATION SESSION ENGINE

### Step 1 — Part 1

Automatic question set.

### Step 2 — Part 2

```text
1 min preparation
2 min speaking
```

### Step 3 — Part 3

Examiner receives structured follow-up prompts.

### Step 4 — Observer mode

Observer sees a lightweight checklist:

```text
Fluency
Vocabulary
Grammar
Pronunciation
Idea Development
Answer Relevance
```

### Step 5 — Feedback

After the speaking round:

```text
Candidate reflection
Examiner feedback
Observer feedback
```

Then the system rotates roles.

---

# 10. WHY ROLE-ROTATION MATTERS

The learner does not only speak.

The learner also learns:

```text
How questions are asked
How follow-ups work
What makes an answer understandable
What common problems sound like
How to notice speaking weaknesses
```

This turns passive speaking practice into active speaking analysis.

# 11. 04 — SKILL-SWAP MATCHING

## Purpose

Match learners based on complementary strengths and weaknesses rather than only basic availability.

### Core idea

```text
Student A
Strong Part 2
Weak Part 3

        ↕

Student B
Weak Part 2
Strong Part 3
```

The platform can suggest a practice match because their strengths and weak areas complement each other.

### Matching model

```text
Compatibility
+
Availability
+
Level
+
Target Band
+
Practice Goal
+
Question-Type Strengths
+
Question-Type Weaknesses
=
Suggested Match
```

---

# 12. SKILL-SWAP SESSION

Example:

```text
Student A teaches / demonstrates:
Part 2 structure

Student B teaches / demonstrates:
Part 3 discussion
```

At the end:

```text
What I learned from my partner
What I practised
What I still need to improve
```

This should be connected to each learner's Progress model.

---

# 13. SKILL-SWAP SAFETY

Skill-Swap should never imply that one learner is a qualified IELTS teacher.

Use language such as:

> Practice together.

> Share your approach.

> Compare your answers.

Avoid:

> Teach the official IELTS method.

> Guarantee your partner's band score.

# 14. 05 — STUDY SESSION REPLAY

## Purpose

Turn a live collaborative session into a reusable learning record.

### Core idea

The session does not disappear when the room closes.

The platform creates a structured session summary.

### Example

```text
STUDY SESSION REPLAY

Date
Duration
Participants

Content studied
Questions practiced
Shared highlights
Shared notes
Whiteboard
Group errors
Key decisions
Next recommended practice
```

---

# 15. REPLAY SHOULD NOT MEAN RAW VIDEO ONLY

The core value is not simply replaying a video call.

The replay should be a **learning artifact**.

Example:

```text
47-minute Study Session

Reading Passage 2
Matching Information

9 questions discussed
7 shared highlights
5 shared notes
3 group mistakes

Next Step:
Matching Information Drill
```

The user can return to the important learning events rather than watching the whole session again.

---

# 16. REPLAY + PERSONAL PROGRESS

Group activity is shared.

Learning progress remains personal.

Example:

```text
Study Room:
47 min

Student A:
6/10 questions correct

Student B:
8/10

Student C:
7/10
```

Each learner's own mistakes can be saved to their personal Mistake Book.

The group session itself remains a shared activity record.

# 22. SHARED PAGE ARCHITECTURE

Do not make full desktop screen-sharing the core Study Room architecture.

Preferred:

```text
Shared Route
+
Shared Content State
+

+
```

# 24. MODERATION + SAFETY

Because these are human-to-human features, safety is part of the product architecture.

Required:

```text
Report
Block
Mute
Leave Room
End Session
Moderation Log
```

The service should maintain clear community rules around harassment, spam, inappropriate behaviour and misuse.

Audio/video recording should be opt-in, with clear consent and deletion rules.

---

# 25. PRIVACY RULES

Do not record live audio/video by default.

When recording is enabled:

```text
All required participant consent
       ↓
Recording indicator
       ↓
Storage policy
       ↓
Access control
       ↓
Deletion control
```

Users should understand:

- who can access the recording
- how long it is stored
- whether it can be downloaded
- how it can be deleted

# 27. FEATURE PRIORITY

## Priority 1 — Speaking Partner

Build the basic human matching + speaking room first.

## Priority 2 — Study Rooms

Build shared learning surface + audio/video + annotations + whiteboard.

## Priority 3 — Speaking Role-Rotation

Add structured speaking simulation on top of the room system.

## Priority 4 — Skill-Swap Matching

Use existing performance data to improve matching quality.

## Priority 5 — Study Session Replay

Turn collaborative activity into durable learning data.

This order lets the team build the real-time foundation once and progressively add intelligence to it.

# 33. SUCCESS METRICS

Porchi should not measure Collaborate only by time spent online.

### Discovery

Speaking Partner search → successful match rate

### Activation

Matched → completed first session

### Retention

First session → repeat session

### Learning

Sessions → practice completed

### Quality

Peer feedback completion

### Progress

Targeted weakness → subsequent improvement in practice

### Collaboration health

Report/block rate, room completion and repeat-partner rate

---

# 34. NORTH-STAR METRIC

A useful long-term measure is:

> **Meaningful Collaborative Practice Sessions Completed**

A session should count only when it contains an actual learning activity, not merely an open call.

Example criteria:

```text
Session duration threshold
+
IELTS content opened
+
Practice action completed
```

This keeps the product aligned with learning rather than vanity engagement.
